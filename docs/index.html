Ratchet Loop for AI coding agents

Make your coding agent prove every step.

Claude Code, Codex and other coding agents can build a whole feature from one message. But they often say "done" when a test is missing, a screen doesn't match the design or an edge case is broken. Ratchet Loop checks every step, so you don't have to.

The problem

The agent checks its own work.

When a coding agent builds a feature, the same agent writes the tests, runs them and decides when it's done. Nothing stops it from writing tests that already pass, skipping a check, or calling a screen finished without looking at it.

On a small change, you catch this in review. On a feature with eight steps, the mistakes pile up, and you find them at the end, all at once.

So you end up watching the agent and testing everything yourself.

The fix

Ratchet Loop checks every step for you.

Ratchet Loop splits a feature into small steps. Each step has to pass four gates before the next one starts: its tests, a check against the design, a review by a different AI, and finally your OK.

The agent can't skip a gate. Hooks in your CLI block it.

With Ratchet Loop, you can:

Leave the agent to work

You approve the plan and try the result. In between, it works on its own and posts a one-line update after each step.

Trust it when it says done

A step only counts as done after its tests pass, its screens match the design and a second AI has reviewed the code.

Catch bugs where they start

Each step is checked and committed before the next one starts, so a bug can't hide under later work. Any step can be undone on its own.

Keep the cost in check

Review rounds are capped per step and per run. Paid tools are never used without your OK. When the agent gets stuck, it stops and asks you.

An example

What happens when the agent misses a bug?

Take the example of a manager rejecting a leave request. The agent adds a Reject button, writes tests, and they all pass. But it forgot to make the reason required.

With Ratchet Loop

  2. gate 11 test fails, then all 6 pass✓
  3. gate 2Screen matches the prototype✓
  4. gate 3Reviewer: an empty reason is accepted✕

Bug caught before the commit. Step 4 starts on working code.

On its own, the agent finishes first, reports success, and the bug ships.

With Ratchet, a reviewer from another company finds the bug. The fix comes with a new test, and the step is saved as its own commit before the next one starts.

Compared with TDD

Isn't this just TDD?

TDD is one of the four gates. Asking an agent to use TDD helps, but the agent still runs its own tests, reports its own results and decides when it's done. Ratchet takes those jobs away from it.

Install guide

Questions

Before you ask.

Which coding agents does it work with?

Claude Code, Codex, Gemini CLI and GitHub Copilot CLI. Install it once on your computer for each CLI you use. Claude Code has the strongest safeguards, because its hooks can tell which agent is acting. The Gates page lists what each CLI enforces.

How long does it take?

A small feature usually takes 20 to 60 minutes. Bigger ones take longer. The agent works on its own, so you don't have to watch.

Is it expensive?

It uses more AI time than letting the agent write code unchecked. Ratchet keeps it in check. It limits review rounds per step and per run, uses one reviewer for low-risk steps and cheaper models for simple jobs. It never uses a pay-per-use tool without your OK.

Do I need other AI tools installed?

No. Without them, Ratchet uses a different model from the same company. If you have another tool signed in, like Codex, Gemini, Copilot, Cursor or OpenCode, it reviews first. A model from another company catches different mistakes.

Where does my code go?

Into your project, with one git commit per finished step. If you're on your main branch or have unsaved changes, the agent offers to make a new branch first. Ratchet keeps its notes in a .ratchet/ folder.

Can I stop halfway?

Yes. Say pause. When you're ready, say carry on. You can pick it up in a new chat too. Nothing is lost.

What if I don't like the result?

Say so at the end, like you would to a colleague. Your feedback becomes new steps, and the agent saves the lesson for next time.

What if the reviewers keep finding the same mistake?

The agent offers to add an automatic check, like a lint rule. After that the mistake is caught in seconds. You decide.

The agent says the hooks aren't working.

Close the CLI, open it again in the same folder, and say: Set up Ratchet and continue. If that doesn't work, ask it to check that Ratchet's hooks are installed for this CLI.
