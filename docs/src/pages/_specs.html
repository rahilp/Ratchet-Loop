14Specs and CI

Fits the way your team already works.

If your team writes specs

OpenSpec, GitHub Spec Kit, BMAD

Ratchet builds from the spec you've written instead of making up its own plan. Every scenario gets a test that has to pass, every task is assigned to a step, and if anything is left out, the plan tells you why. As steps pass, Ratchet ticks off the matching tasks in your spec files.

Use Ratchet to build the add-dark-mode change. Use Ratchet to build story 1.3.

No spec tool? The plan you approve is the spec. After your first feature, the agent asks once if you'd like a simple record of what's been built.

Keep the checks running in CI

"Ask your agent to set up CI."

Ratchet writes a GitHub Actions workflow that runs your test command and every automatic check saved during your runs, on every push and pull request.

The AI review gates don't run in CI, because CI machines don't have the agent tools and sign-ins those gates need. If a hand-written workflow already exists, Ratchet never replaces it.
