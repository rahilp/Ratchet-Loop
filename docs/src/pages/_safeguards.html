Eight safeguards. Enforced by hooks.

When a step is hard, an agent takes shortcuts. It deletes a failing test, edits a test until it passes, or approves its own review. Hooks stop that. A hook is a small program your CLI runs before and after the agent acts. Ratchet's hooks check each action against these rules.

R1

Results come from Ratchet

The agent can't report that tests pass. Ratchet runs them. Reviewers can't report approval. Ratchet decides the verdict from their findings.

R2

Tests come first

A test that passes before the feature exists is rejected.

R3

Tests can't be removed

Every planned test must still exist each time the tests run.

R4

Changes reset the gates

Each gate result is tied to the code it checked. If the code changes, the gates run again.

R5

Same state or no result

Two screenshots are only compared if they show the same state. Otherwise the comparison is redone.

R6

Screen reviewers are isolated

They work in a folder with only the screenshots and the design file. They never see the code, the chat or your agent's instructions.

R7

Records are protected

Ratchet's records can't be edited by hand. In Claude Code, each review can only be written by its assigned reviewer.

R8

No stopping early

The agent can't end its turn while a gate is open, unless it is waiting for you, stuck or paused.
