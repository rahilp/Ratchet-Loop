09Cost and budgets

Checking costs more. You set the limit.

Reviewing every step uses more AI time than letting the agent run unchecked. Ratchet caps the number of review rounds, spends more on risky steps and less on safe ones, and never uses a pay-per-use tool unless you say so.

Default limits. You can change any of them in .ratchet/config.json.

C1

Reviewers match the risk

Low-risk steps get one reviewer. Normal steps get two. High-risk steps get four. The plan shows each step's risk before you approve it.

C2

The right model for each job

Planning, coding and reviewing use a strong model. Writing test plans uses a cheaper one. Running tests uses the cheapest. You can change any of them in the config.

C3

Subscriptions first

Tools you already pay a flat monthly rate for are used first. A pay-per-use tool gets nothing, not even a test call, until you reply pay per use: <model>.

C4

Later rounds cost less

Round 1 asks every reviewer. After that, only reviewers with an open problem are asked back. A small fix of 20 lines or fewer gets one reviewer.

C5

Small notes don't block

From round 3, minor findings no longer hold up a step. They are listed at the end and you decide which to fix.

C6

No paying twice

If two reviewers would be the same model doing the same review, it runs once. A single flaky test failure does not use up an attempt.

C7

No paying for tools that are down

A signed-out tool is skipped for six hours. A tool that is out of credits is skipped until its reset time. Every project on your machine shares this list.

C8

Repeat mistakes get a rule

If reviewers flag the same mistake twice, the agent offers to add a check, like a lint rule. After that it is caught in seconds, before a reviewer is paid to find it.

Ratchet counts rounds and attempts, not dollars. For what you spent, check your AI provider's dashboard.
