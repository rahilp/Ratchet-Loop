How it works

You talk to your agent like normal. It runs Ratchet for you.

  1. 1

    Describe it

    One sentence or two. Use Ratchet to build this feature: managers can approve or reject leave requests, with a reason.

  2. 2

    Approve the plan

    The objective, the steps, what done means, the risk and who reviews. New screens come with a clickable prototype. Say yes and it locks.

  3. 3

    Walk away

    Tests first, and they must fail. Then code until they pass. Then reviewers go looking for problems. Every finished step is its own commit.

  4. 4

    Try it, sign off

    Say approved if you're happy. If not, say what's wrong in your own words. Your feedback becomes new steps through the same gates.

You're needed twice. Once to OK the plan, once at the end.

The four gates

Every checkpoint clicks through four gates. In order. No skipping.

Gate 1Open

Tests

Tests are written before the code. At least one has to fail on an assertion. Then all of them have to pass.

  • Ratchet runs the tests itself and reads each result one by one.
  • A test that crashed, was skipped or never ran doesn't count.
  • Planned tests freeze after their first failing run. Changing one needs your OK.
Gate 2Open

Looks right

Tests can't tell you the button is the wrong blue. So two reviewers look at the screen the way a fussy designer would.

  • Reference and real app are put in the same state and screenshotted side by side.
  • One checks how it looks. One checks how it behaves.
  • They never see the code or the chat, so nobody can tell them it's fine.
Gate 3Open

Review

A second AI, from another company if you have one, tries to break the code. Review keeps going until nobody has a blocking finding.

  • Low risk gets one reviewer. Normal gets two. High gets four.
  • A review only counts when it was signed for that round.
  • Small nitpicks are saved for you at the end instead of starting another round.
Gate 4Open

You

You try it and say yes. Only a real message from you counts. A thumbs-up, an ok or a yes with a but on the end doesn't.

  • Approval replies are exact: yes, go ahead, approved.
  • A yes only answers the question it belongs to.
  • Messages your CLI sends on its own are never taken as yours.

Why the gates hold

The agent can't argue its way past. It can only fix the problem.

Hooks sit between your agent and the exit. They stop it skipping a gate, quitting early, or quietly lowering the bar. When a gate runs out of tries, the run stops and the agent comes back to you with options. Nothing gets lowered unless you pick it.

  • Tests can't be deleted to make the suite pass.
  • The approved plan, design file and prototype are locked.
  • Screenshots that don't match the same state are thrown out and redone.
  • Accepting a finding takes your own words and your own reason, written down.

Who reviews the work

A second opinion from somebody else.

The model running your agent could be Claude, GPT, Gemini or a Copilot model. Ratchet doesn't care which. What matters is that the reviewer is someone different. A second company tends to catch what the first one misses.

  1. 1

    Another company

    Any AI tool installed and signed in on your machine that works.

  2. 2

    Another model

    Same company, different model. Sonnet reviewing work done by Opus.

Install once per computer

Three messages. That's the whole setup.

  1. 01

    Ask your agent to install it

    Please install Ratchet Loop from https://github.com/rahilp/Ratchet-Loop and set it up for this CLI.

    It asks before it changes anything. Part of setup is adding hooks. Hooks are what stop the agent skipping a gate.

  2. 02

    Restart your CLI, then say

    Set up Ratchet and continue

    Hooks only load when the CLI starts. The agent checks they work and tells you Ratchet is ready.

  3. 03

    Build something

    Use Ratchet to build this feature: describe it in a sentence or two.

    Keep it to one feature. A few sentences usually becomes three to eight steps.

You need a git repository and Python 3. Building screens? Ratchet also uses Node and Playwright for screenshots, and offers to set them up.

If your team writes specs

OpenSpec, Spec Kit, BMAD. The spec says what to build. Ratchet makes sure it was built.

Every scenario gets a test that has to pass. Every task is assigned to a step. If anything is left out, the plan tells you why. As steps pass, Ratchet ticks off the matching tasks in your spec files.
