A second opinion. From a different AI.

An AI that checks its own code tends to miss its own mistakes. So Ratchet has a different AI review every step. If you have a tool from another company, that one goes first.

Who reviewsThe agents

Who reviews. In this order.

A model from another company makes different mistakes, so it catches more of yours. Ratchet picks the most different reviewer you have installed, in this order. Your agent can run on Claude, GPT, Gemini or a Copilot model.

Who gets asked, in order

  1. 1

    Another company

    Any AI tool on your machine that is installed and signed in.

  2. 2

    Another model

    Same company, but a different model. For example, Sonnet checks work done by Opus.

  3. 3

    The same model

    Only if there is nothing else to use.

How many look, by risk

Low

1 reviewer. Only big problems hold up the step.

Normal

2 reviewers. The default.

High

4 reviewers. The plan must say which users could be harmed, and how.

Aimed at your users

Each reviewer starts with the goal of the plan. A finding has to say which user it hurts and how. The worse the harm, the more serious the finding.

A broken reviewer is swapped out

If one tool fails, only that tool is skipped. Another working tool from a different company takes its place.

Cut-off replies get one retry

If a review stops halfway, the reviewer is asked once more before it counts as a failure.

Stuck steps get a fresh look

If a step fails review twice in a row, a new reviewer reads the goal and the history. It either suggests a simpler step or asks you.

Thirteen agents. One job each.

One agent doing every job tends to cut corners on the jobs it likes least, like testing and review. Ratchet gives each job its own agent with its own instructions. The one that writes the code never reviews it. Pick one to read its definition.

A2Plan stage

Checkpoint planner

Splits the feature into small, ordered checkpoints, each with a plain “done when” list and the gates that apply.

agents/ratchet-checkpoint-planner.md

A3Plan stage

Design system

Writes DESIGN.md, a file with the exact colours, fonts and spacing of your app.

agents/ratchet-design-system.md

A4Plan stage

Prototyper

Builds a clickable prototype for you to try. You approve it before the real build starts.

agents/ratchet-prototyper.md

A5Plan stage

Test planner

Plans each checkpoint’s test cases before any code exists.

agents/ratchet-test-planner.md

A6Build stage

Test writer

Turns the planned cases into real tests, written before the code, so at least one fails first.

agents/ratchet-test-writer.md

A7Build stage

Implementer

Writes the code for exactly one checkpoint. Never edits tests.

agents/ratchet-implementer.md

A8Build stage

Test runner

Runs Gate 1 and, when it fails, returns a short diagnosis instead of a wall of logs.

agents/ratchet-test-runner.md

A9Build stage

Fixer

Fixes every open review finding, or rebuts a wrong one with evidence. Never weakens a test.

agents/ratchet-fixer.md

A10Review stage

Adversary

Assumes the code is wrong and tries to prove it. Approves only by finding nothing.

agents/ratchet-adversary.md

A11Review stage

Visual reviewer

Compares screenshots with the design. Lists each difference it sees, and where.

agents/ratchet-visual-reviewer.md

A12Review stage

Behaviour reviewer

Clicks through the same journey on both and lists every difference in how they respond.

agents/ratchet-behavior-reviewer.md

A13Review stage

Variant writer

Hides the same mistake in new code, to prove a new check really catches it.

agents/ratchet-variant-writer.md
