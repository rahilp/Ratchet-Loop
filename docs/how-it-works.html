How Ratchet Loop builds a feature

You describe a feature in a sentence or two. The agent plans it as a short list of steps and shows you the plan. Once you say yes, each step is built and checked before the next one starts, and you try the finished feature at the end.

The ideaA whole runInside one step

A step is done when the proof is in

Code that looks right can still be wrong. So Ratchet doesn't count a step as done when the code is written. It waits for the proof too: the test results, the screen check and the review. A step and its proof together are called a checkpoint.

A run, from your request to your sign-off

You're needed twice: once to OK the plan and once at the end. Everything in between runs on its own, and the agent comes back to you if it gets stuck.

You ask

Describe one feature in a sentence or two. That usually becomes three to eight checkpoints. If it would need more, split it into two features.

If something is unclear, the agent asks instead of guessing.

  • Ratchet's hooks are working in this CLI
  • Another AI can review: Codex, signed in
  • No spec written yet, so the plan will be the spec
  • The app starts and the tests run
  • You're on your main branch. Start a new one?

Quick checks

Before it plans, the agent runs a few quick checks. Do Ratchet's hooks work? Which other AI tools can review? Is there a spec already? Does the app start, and do the tests run? If anything is in the way, it tells you in one message and offers to fix it.

The plan

The plan starts with the objective: who the feature is for, what they need, what done means and what is out of scope. Then it lists the checkpoints. Each one has a done-when list, a risk level and its reviewers.

New screens come with a clickable prototype. When you approve, the plan, the design file and the prototype are locked.

Building

Checkpoints are built one at a time. Tests come first and must fail. Then the code is written until they pass. Then reviewers look for problems, and each one is fixed and checked again.

Each finished checkpoint is its own git commit. You get a one-line update for each.

If it gets stuck

Each gate has a limited number of tries. When they run out, the run stops. The agent quotes the problem and offers two or three options, labeled A, B and C, and marks the one it recommends. You reply with a letter.

A check is only lowered or skipped if you choose that option.

AgentAll 4 steps are locked. To try it: open Team leave, reject a request, and leave the reason empty. You should see "A reason is required". Reviewers also noted 2 small things that didn't block. Want either fixed?

Sign-off

When every checkpoint is done, the agent tells you what to try. It also lists minor issues the reviewers noted, and asks whether you want any of them fixed.

Reply "approved" to finish. Otherwise, describe what's wrong. Your changes become new checkpoints and go through the same gates.

Example

Can I approve each step instead?

Yes. By default you approve the plan and the finished feature. You can ask to approve each step instead. You can also say "pause" at any time and "carry on" later, even from a new chat.

What happens inside one step

Each step goes through the same eight stages, and each stage has its own agent. The one that writes the code never gets to judge it.
