# Security Policy

## Reporting a vulnerability

Please report security vulnerabilities privately. Do not open a public issue,
pull request, or discussion for a suspected vulnerability, because that
discloses it before a fix is available.

Use GitHub's private vulnerability reporting:

1. Go to the repository's **Security** tab.
2. Click **Report a vulnerability** to open a private advisory.
3. Or use the direct link:
   https://github.com/rahilp/Ratchet-Loop/security/advisories/new

In your report, please include:

- a description of the issue and why you believe it is a vulnerability,
- the version or commit you tested,
- steps to reproduce, a proof of concept, or a failing test, and
- the impact you expect (for example data loss, unauthorized access, or
  bypassing a quality gate).

Reports are received only by the maintainer and are kept private until a fix
is released.

## Supported versions

Security fixes are provided for the current 1.x release line. Earlier,
pre-1.0 versions are not supported; please upgrade to the latest 1.x release
to receive security updates.

| Version | Supported |
| ------- | --------- |
| 1.x     | Yes       |
| < 1.0   | No        |

## What to expect

- **Acknowledgement:** the maintainer aims to acknowledge your report within
  three business days.
- **Assessment:** after triage you will get an initial assessment and, if the
  report is accepted, a rough plan and timeline for a fix.
- **Updates:** you will be kept informed as the fix progresses, and told when
  a release containing it is available.
- **Disclosure:** disclosure is coordinated with you. The advisory is
  published once a fixed version is out, and you will be credited for the
  report unless you ask to remain anonymous.

If a report turns out not to be a vulnerability, the maintainer will explain
the reasoning so you can follow up if you disagree.
